# HUDHUD CONTROL — دليل جاهزية الإنتاج

**التاريخ:** 2026-11-16
**النطاق:** البوابة (portal) فقط. التطبيقات السبعة لها مستندات تشغيلها الخاصة في مجلداتها.

## الحالة الحالية الصادقة

| الجانب | الحالة | المتطلب المتبقي |
|---|---|---|
| الشيفرة | مكتملة (المراحل 1-3) | دمج PR #4 بموافقة |
| قاعدة البيانات | ترحيلات idempotent (0001 + 0002) | تشغيل `npm run db:apply` على إنتاج |
| المصادقة | email/password + disableSignUp + seed | تشغيل `db:seed` بمتغيرات سرية |
| الاختبارات | مكتوبة (وحدة RBAC/registry/audit/health/ip/rate-limit) | تشغيل فعلي (CI أو يدوي) — **NOT RUN حتى الآن** |
| البناء | غير مُتحقق بعد | `npm run typecheck && npm run build` |
| CI | محظور — نطاق workflow غير متوفر | إعادة ربط GitHub بنطاق workflow |
| الأسرار | لا سر ملتزم؛ .gitignore يغطي env و*.dump | ضبط secret manager في الاستضافة |

## خطوات التشغيل الإنتاجي (بترتيب صارم)

### 1. المتطلبات
- Node 22+
- PostgreSQL (قاعدة hudhud_core، مستخدم مخصص بصلاحيات محدودة على هذه القاعدة فقط)
- سر BETTER_AUTH_SECRET من `openssl rand -base64 32`
- عناوين التطبيقات السبعة (اختيارية — بدونها تظهر «غير معروف» بصدق)

### 2. التحقق قبل النشر (كل أمر يجب أن ينجح فعليًا)
```bash
cd portal
npm install
npm run typecheck   # يجب أن يمر بلا أخطاء
npm run lint        # يجب أن يمر بلا أخطاء
npm test            # يجب أن تمر كل حالات vitest
npm run build       # يجب أن ينجح البناء
```
**إذا فشل أي أمر — لا نشر.** أصلح أولًا. هذه الأوامر لم تُشغَّل بعد (لا بيئة تنفيذ متاحة للوكيل)؛ المشغل يشغلها ويوثق النتائج الفعلية.

### 3. قاعدة البيانات
```bash
# ترحيلات idempotent — آمنة للتكرار
npm run db:apply

# إنشاء المدير الأول — متغيرات من secret manager، لا في أي ملف
HUDHUD_ADMIN_EMAIL=... HUDHUD_ADMIN_PASSWORD=... npm run db:seed
```

### 4. النسخ الاحتياطي (قبل أول تشغيل إنتاجي)
```bash
HUDHUD_BACKUP_DIR=/مسار/خارج/المستودع npm run db:backup
```
تحقق من ظهور السجل في صفحة /backup. الاستعادة: dry-run افتراضيًا؛ `--confirm` يتطلب موافقة صريحة موثقة.

### 5. التشغيل
```bash
npm run start
```
- ضع البوابة خلف TLS (termination في reverse proxy).
- لا تكشف أي HUDHUD_APP_*_URL خارجيًا — فحوصات الصحة من الخادم فقط.

### 6. ما بعد النشر (فحص قبول فوري)
- [ ] الدخول بمدير seed يعمل
- [ ] لوحة القيادة تظهر التطبيقات السبعة بحالات فعلية
- [ ] صفحة المراقبة تُظهر لقطات بعد أول فحص
- [ ] مركز التدقيق يسجل أحداث الدخول والفحص
- [ ] صفحة المزودين تعرض الحضور/الغياب الصحيح
- [ ] تغيير دور مستخدم ثانٍ يعمل، وتغيير الدور الذاتي مرفوض (self_demotion_forbidden)
- [ ] نسخة احتياطية واحدة على الأقل ظاهرة في /backup

## حدود المسؤولية

- **ما هو جاهز**: شيفرة البوابة كاملة، ترحيلات idempotent، اختبارات وحدة، سكربتات تشغيل موثقة، عزل صارم (hudhud_core فقط).
- **ما يتطلب قرار المشغل**: الاستضافة، DNS/TLS، secret manager، تشغيل الاختبارات والبناء، PostgreSQL HA (المرحلة 4 — قرار موارد)، تفعيل CI (يتطلب نطاق workflow).
- **ما لا تفعله البوابة أبدًا**: لمس قواعد التطبيقات، عرض أسرار، تنفيذ استعادة من الواجهة، فرض SSO.

## سياسة الأسرار في الإنتاج

| المتغير | المصدر الموصى به |
|---|---|
| DATABASE_URL | secret manager — مستخدم hudhud_core بصلاحيات DDL+DML على hudhud_core فقط |
| BETTER_AUTH_SECRET | secret manager — `openssl rand -base64 32` |
| HUDHUD_ADMIN_PASSWORD | secret manager — توليد قوي، تدوير بعد أول دخول |
| HUDHUD_APP_*_URL | تكوين النشر — عناوين داخلية |
| مفاتيح مزودي التطبيقات (GOOGLE_/GITHUB_/RESEND_/REDIS) | secret manager لكل تطبيق صاحب المتغير — البوابة تقرأ الحضور فقط |
